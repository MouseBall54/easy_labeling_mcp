# 폴더 전체 라벨링

[공통 가이드](../MCP_PLAYBOOK.md)에서 시작한다. 전체 라벨 생성 요청에는 적용과 저장이 포함된다. 미리보기 요청이면 후보와 판단 근거를 기록한다.

## 1. 입력 파일과 저장 위치 확정

1. `app_state`와 `list_images`로 앱에 열린 전체 파일 목록을 확보한다. 확장자를 포함한 파일명으로 작업 목록을 만든다. 디스크 파일 수가 다르면 그 차이를 기록한다. 예를 들어 앱 15장과 디스크 20장이면, 현재 로딩된 이미지 요청의 분모는 앱의 15장이다.
2. 쓰기 전에 `list_images {"storage":true,"offset":0,"limit":20}`으로 페이지를 조회한다. 모드별 `paths`와 `conflictingImages`를 보고 공유 출력이 있는 이미지만 보류하고 나머지는 처리한다. 충돌 대상까지 라벨링해야 하면 원본은 보존하고 작업 복사본에서 `sample (1)__jpg.jpg`처럼 고유 이름을 사용한다. 원본과 작업 파일의 대응표를 남기고, 기존 결과는 대응 이미지가 확인된 경우에만 옮긴다.
3. 복사본은 앱의 `open_folder`로 열고 `app_state`와 `list_images`로 범위와 활성 라벨 위치를 재확인한다. 앱이 열기를 거절하면 공통 종료 규칙을 따른다. `read_error`인 출력은 원인을 적고 다음 대상으로 진행한다. 벤치마크에서는 원본 이미지와 정답 폴더의 전후 해시를 비교한다.

## 2. 대상과 클래스 확정

- 기준이 있으면 그 정의를 따른다. 선택을 위임받았으면 보이는 대표 객체군을 정하고 경계 기준을 한 줄로 기록한다. 예를 들어 PCB의 IC를 고르면 본체 윤곽을 기준으로 하고 핀은 제외할 수 있다. 같은 객체에는 모든 이미지에서 같은 ID를 쓴다. 대상이 다른 이미지에서는 확인 가능한 객체군과 별도 ID를 사용할 수 있다.
- [공통 클래스 확인 절차](../MCP_PLAYBOOK.md#2-라벨-상태에-따라-문서-선택)로 활성 이름과 ID를 확인하고, 필요한 경우 새 YAML을 생성한다. Detection과 Segmentation에서 같은 양수 ID를 사용할 수 있으면 매핑이 단순하다. 기존 Detection 클래스가 `0`이면 변환 시 양수 마스크 ID를 지정한다. [앱의 클래스 파일 안내](../../easy_labeling/docs/FEATURES_AND_OPTIONS_KO.md)

## 3. 이미지별 적용과 저장

1. **Detection** · 확인한 물체의 원본 이미지 픽셀 경계를 모아 `add_boxes`로 적용한다. 반복 패턴은 `find_similar`나 확인된 템플릿으로 미리보고, 검증된 모델이 있으면 [추론 절차](AUTOMATION.md)를 활용한다. 모델·템플릿이 없어도 이미지를 볼 수 있으면 [캡처 좌표를 환산](../MCP_PLAYBOOK.md#캡처와-좌표)해 확인한 윤곽으로 박스를 잡는다. 기존 박스는 실제 누락·오류만 보완한다. [공통 저장 절차](../MCP_PLAYBOOK.md#저장-경로와-결과-확인)로 경로와 박스 수를 확인한다.
2. **Segmentation** · 같은 이미지의 확인된 Detection 박스로 `boxes_to_masks`를 미리본다. 특정 물체는 `segment_ai`에 박스를 전달할 수 있다. 면적과 경계가 의도에 맞는 후보는 `resultId`와 `accept`로 적용하고, 기존 마스크의 누락을 채울 때는 `backgroundOnly:true`를 미리보기와 적용 양쪽에 유지한다. `get_regions {"limit":0}`으로 적용 후 픽셀·영역 수를 읽고, [공통 저장 절차](../MCP_PLAYBOOK.md#저장-경로와-결과-확인)로 디스크 결과를 확인한다. 후보 판단은 [세그멘테이션 가이드](SEGMENTATION.md)를 따른다.
3. 편집 전에 현재 이미지와 모드를 확인한다. 두 작업을 함께 요청받으면 첫 이미지에서 Detection을 저장한 뒤 같은 이미지의 Segmentation까지 저장한다. 이후 같은 순서로 전체 작업 목록을 처리하거나 모드별로 묶어 전환 횟수를 줄인다. 일부 후보만 불명확하면 확인된 항목부터 저장한다. 프롬프트를 바꿀 때는 주변 포함이나 경계 잘림처럼 해결할 문제를 정한다. 변경 근거가 없거나 같은 문제가 반복되면 그 후보를 보류하고 다음 대상으로 이동한다.

이미지를 읽을 수 없는 클라이언트는 기존 박스, 검증된 모델·템플릿 또는 확인된 좌표가 있는 이미지부터 진행한다. 위치 근거가 없는 이미지만 보류한다. 과거 추론 폴더가 있다면 이미지 대응과 클래스 의미가 확인된 후보를 사용한다. 저장 확인은 수치로 하고, 시각 확인은 [공통 캡처 규칙](../AGENTS.md)을 따른다.

## 4. 완료 판정과 기록

- 초기 목록의 각 이미지에 대해 Detection과 Segmentation 상태를 각각 기록한다. **저장 확인 / 기존 유지 / 대상 없음 확인 / 일부 저장·보류 / 미처리** 중 해당 상태를 쓰고, 박스 수·마스크 픽셀/영역 수와 보류 이유를 남긴다. 쓰기 오류나 응답 끊김이 있으면 먼저 저장 상태를 읽고 중복 적용을 피한다.
- 두 모드 모두 처리 결과가 확인된 이미지 수를 전체 분모와 함께 보고한다. 일부 저장·보류나 미처리가 있으면 해당 파일명을 남긴다. 미리보기 후보 수와 기존 라벨 수는 이번 실행에서 새로 저장한 수와 구분한다. 정답이 있을 때만 F1·IoU를 정확도로 보고한다. 예전 추론 결과와의 비교는 모델 출력 간 일치도로 기록한다.
- 로그에는 모델·클라이언트·앱 버전, 원본과 작업 경로, 클래스 ID 매핑, 이미지별 생성·저장 수, 실패한 도구와 오류, 우회 결과를 적는다. 측정했다면 전체 소요 시간, MCP 호출·캡처 수, 첫 저장까지 걸린 시간도 남긴다.
