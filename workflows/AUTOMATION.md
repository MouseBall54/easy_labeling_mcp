# 템플릿·레이아웃·YOLO

`app_state`에서 활성 폴더와 현재 이미지를 확인한다. 수치로 판단할 수 있는 경우에는 캡처 없이 진행한다. 필요한 경우 [공통 캡처 규칙](../AGENTS.md)을 따른다.

## 템플릿 매칭과 레이아웃

1. `list_templates`로 프리셋·레이아웃을 확인한다. 프리셋의 기존 라벨 처리 정책이 응답에 없으면 앱에서 확인한다.
2. `run_template_matching` 또는 `find_similar`를 미리보기로 실행한다. 점수·후보 수와 기존 라벨과의 충돌을 확인한다. 잘린 목록을 전체로 해석하지 않는다. `apply_layout`은 실제 변경이므로 레이아웃과 배치 위치가 확정된 경우 호출한다.
3. 승인된 범위에서 한 장에 적용하고, 도구 응답과 클래스별 개수로 검증한다. 배치 실행은 대상별 건너뜀·오류를 따로 집계한다. 저장 확인은 [공통 저장 절차](../MCP_PLAYBOOK.md#저장-경로와-결과-확인)를 따른다.

## YOLO 추론

1. `inference_status`를 조회하고 필요하면 지정 모델을 `load_model`로 로드한다. `get_classes`로 앱 클래스 매핑이 모델과 일치하는지 확인한다. 시작 전에 원본 폴더의 미저장 변경을 확인한다.
2. 한 장에서 `run_inference`를 실행한다. 응답의 `saves`에서 실제 출력 경로와 박스 수를 확인하고, `app_state`로 활성 `inference-*` 폴더를 확인한 뒤 `list_images`의 `storage:true`로 재조회한다. 정확한 클래스와 좌표가 필요하면 `read_labels`도 사용한다.
3. 전체 실행은 한 장의 결과가 맞고 그 범위가 요청된 경우 진행한다. 라벨 폴더 탭 전환은 앱에서 수행한다. 테스트에서는 추론 전후 원본 라벨 파일의 해시를 비교한다.
