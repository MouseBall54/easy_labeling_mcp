# Detection 박스 라벨링

먼저 `app_state`로 대상과 모드를 확인한다. 쓰기 전에는 [공통 저장 절차](../MCP_PLAYBOOK.md#저장-경로와-결과-확인)를 따르고, 시각 확인은 [공통 캡처 규칙](../AGENTS.md)을 적용한다.

## 빈 이미지에서 시작

1. 사용자가 지정한 물체와 클래스가 맞는지 `get_classes`로 확인한다. 확인된 픽셀 좌표가 있으면 캡처를 생략한다. 좌표가 없고 이미지에서 대상을 판별할 수 있는 작업이면 필요한 범위만 한 번 캡처한다.
2. 사용할 근거에 따라 하나를 선택한다.
   - **지정 좌표 또는 확인한 윤곽** → `add_boxes`에 박스를 묶어서 전달한다.
   - **반복 구조의 기준 영역 또는 기존 템플릿** → 확인한 픽셀 `region`과 `classId`로 `find_similar`, 저장된 프리셋이면 `run_template_matching`을 미리보기로 실행한다. 후보의 위치와 클래스가 맞는지 확인한 뒤 적용한다.
   - **지정된 YOLO 모델** → [자동화와 추론](AUTOMATION.md#yolo-추론)의 한 장 검증을 따른다. 출력은 별도 `inference-*` 폴더에 저장된다.
3. 확인된 박스만 묶어 적용하고 개수와 클래스 분포를 확인한다. 대상이 수백 개면 검증된 모델이나 프리셋으로 후보를 먼저 만들고, 근거가 필요한 예외와 대표 표본에 검수 시간을 쓴다. 경계 조정이 필요하면 새 ID만 [Refine 미리보기](REFINE.md)에 전달한다. [결과 확인과 저장](#결과-확인과-저장) 후 요청 범위의 다음 이미지로 진행한다.

빈 이미지에서는 비교할 기존 박스가 있어야 하는 간격·누락 분석을 건너뛴다. 신뢰할 좌표·기준 영역·프리셋·모델이 없고 이미지를 판독할 수 없으면 필요한 근거를 요청한다.

## 기존 박스 검수와 수정

| 상황 | 호출 순서 | 판단 기준 |
|---|---|---|
| 폴더에서 문제 이미지 찾기 | `review_folder {}` → 문제 유형과 개수로 우선순위 결정 → `analyze_boxes {"images":["a.png"],"limit":1}` | 이 분석은 디스크에 저장된 라벨을 읽는다. 결과 좌표는 `units`를 보고 해석한다. |
| 현재 이미지 검수 | `analyze_boxes {"limit":20}` → `capture_view {"annotationIds":["…"]}` | 후보 수는 `counts`를 사용한다. 필요한 ID만 최대 36개씩 한 캡처에 묶는다. 빈자리는 이미지 픽셀 `region`으로 확대한다. |
| 중복 수정 | `get_boxes {"ids":["…"]}` → 필요하면 두 박스를 같이 캡처 → `delete_boxes {"annotationIds":["…"]}` | 두 박스가 같은 물체를 덮고 남길 박스의 근거가 명확할 때만 삭제한다. 겹침 점수나 ID 순서만으로 삭제 대상을 고르지 않는다. |
| 누락 추가 | 빈자리 확대 → `add_boxes {"boxes":[…]}` → 새 ID만 [Refine 미리보기](REFINE.md) | 실제 윤곽, 인접 물체와의 분리, 클래스 근거가 확인된 경우에만 추가한다. |
| 클래스 수정 | `get_classes {}` → 근거 있는 변경을 `update_boxes {"updates":[{"annotationId":"…","classId":"…"}]}`로 묶음 | 규칙 적용이 요청되면 먼저 `get_refine_settings {}`로 대상·목적 클래스와 밝기 조건을 읽고 `run_reclass {"dryRun":true}`를 확인한다. |

- 다음 이미지에서 이전 `annotationId`를 재사용하지 않는다. 목록 대신 개수만 필요하면 `get_boxes {"limit":0}`, 확인할 대상이 정해졌으면 `ids`를 사용한다. 후보 페이지의 개수와 전체 개수를 구분한다.
- 보고할 범위를 먼저 정한다. 폴더 전체의 겹침·빈자리 합계가 필요하면 `list_images`로 파일명을 얻고 `analyze_boxes`의 `images`로 저장 라벨을 검사한다. `review_folder`에 겹침이 없다는 응답을 `analyze_boxes`의 겹침 후보가 0개라는 뜻으로 해석하지 않는다.
- 구조적 오류와 후보를 구분한다. 수치 검수만 요청됐으면 `app_state` → 필요한 요약 조회 → 보고로 끝낸다. 근거 이미지가 필요한 읽기 전용 검수는 이미지당 한 번을 기본으로 사용한다. 두 번째 캡처는 다른 후보나 영역이 남았을 때만 사용한다. 검토하지 않은 후보가 더 있으면 그 수를 적는다.
- 이미지별 문제 수는 해당 `images[].name`과 `issues[].type`으로 확인한다. `review_folder`의 `boxIndexes`는 문제가 있는 박스 위치다. 총 박스 수는 명시적인 `boxCount`·`total`·`boxes` 개수 필드에서만 가져오고, 개수 필드가 없으면 보고에서 생략한다. 응답이 잘렸으면 전체 집계와 표시된 항목을 구분한다.
- 한 이미지에서 같은 종류의 변경은 한 호출로 묶는다. 호출 직후 변경 수와 조회값을 비교한다. 좌표는 이미지 픽셀 경계이고 `read_labels`의 저장 좌표는 정규화 값이다.

### SEM 샘플의 크기별 클래스

검수를 마친 SEM 샘플 두 장에 크기 분류를 요청하면 기존 클래스 `10`의 박스만 처리한다. `get_boxes`로 읽은 이미지 픽셀 좌표에서 `(x1 - x0) × (y1 - y0)`를 계산한다. 반올림 전에 아래 기준을 적용한다.

| 박스 면적 | 클래스 ID |
|---|---:|
| 300 px² 미만 | 13 |
| 300 px² 이상, 700 px² 미만 | 14 |
| 700 px² 이상 | 15 |

숫자 계산은 로컬 코드로 수행한다. 이미지별로 `update_boxes` 한 번에 ID와 새 `classId`만 보내고 `save` 후 다시 열어 클래스별 개수를 확인한다. 두 컷에서 작은 박스와 중간 크기 박스가 나뉘는 구간을 보고 정한 샘플 전용 기준이다. 배율이나 해상도가 다른 이미지에서 물리적 크기를 비교할 때는 보정 정보가 필요하다.

## 결과 확인과 저장

- 저장 요청이 있으면 [공통 저장 절차](../MCP_PLAYBOOK.md#저장-경로와-결과-확인)로 실제 경로와 박스 수를 확인한다. 클래스별 캔버스 박스 수는 `get_boxes {"limit":0}`, 저장 좌표가 필요할 때는 `read_labels {"image":"a.png"}`를 사용한다. 확인을 마친 이미지에만 `set_review_status {"status":"reviewed"}`를 호출한다. Undo/Redo 검증은 테스트 복사본에서 수행한다.
