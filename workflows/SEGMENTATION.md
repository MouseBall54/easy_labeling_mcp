# Segmentation 마스크 작업

공통 시작과 분기는 [MCP_PLAYBOOK.md](../MCP_PLAYBOOK.md)를 따른다. 이 문서는 Segmentation에서 **후보 생성 → 필요한 영역만 적용 → 결과 확인**의 판단 기준을 정한다.

## 판단 기준

- 데이터셋 기준에서 **대상과 클래스 ID, 윤곽에 포함할 픽셀, 맞닿거나 잘린 물체의 처리**를 확인한다. 있으면 대표 정답 마스크 한 장을 기준으로 삼는다. 기준이 비어 있으면 명확한 영역만 후보로 만들고, 판단이 갈리는 부분은 위치와 이유를 남긴다.
- 마스크는 픽셀마다 클래스 하나를 저장하며 `0`은 배경이다. 같은 클래스의 물체가 이어지면 연결 영역 하나로 집계될 수 있다. 개별 물체 보존이 필요한 작업에서는 접촉부를 따로 확인한다.
- 수치로 판정할 수 있는 후보부터 처리한다. 시각 판정이 필요한 영역에만 [공통 캡처 규칙](../AGENTS.md)을 적용한다. 이미지 결과를 읽을 수 없는 모델이나 클라이언트에서도 수치 검수를 진행하고, 시각 확인이 필요한 후보는 미확정으로 보고한다.

## 빈 마스크에서 시작

1. **Detection 박스가 있으면** `boxes_to_masks`로 한 장을 미리보기한다. 박스와 마스크의 클래스 매핑을 확인하고, 출력 클래스가 다른 박스는 `boxClassIds`로 묶어 각 호출에 `classId`를 지정한다. 특히 Detection 클래스 `0`에는 배경이 아닌 출력 ID가 필요하다.
2. **Detection 박스도 없으면** 확인된 물체마다 박스 프롬프트 하나를 만들고, 같은 출력 클래스끼리 묶어 `segment_ai`로 미리보기한다. 이웃이 함께 잡힌 후보는 그 이웃에 음성 점을 추가해 프롬프트를 좁힌다. 사용자가 정확한 도형과 칠할 클래스를 지정했다면 `paint_mask`를 사용한다.
3. `pixels`, `fill`(박스 변환), `score`, `edgeFit`을 예상 크기와 경계에 대조한다. 점수는 확인 순서를 정하는 데 쓴다. 빈 결과, 지나치게 작거나 큰 결과, 이웃을 덮는 결과는 근거를 확인할 때까지 보류한다. 고정 임계값은 대표 표본에서 검증된 경우에만 재사용한다.
4. 적용 요청이 있으면 가장 최근 미리보기의 `resultId`와 확인한 `accept` 인덱스를 같은 도구에 보낸다. 미리보기에서 `classId`를 지정했으면 적용에도 같은 값을 보낸다. 배경만 채우는 경우 `backgroundOnly:true`를 두 호출에 모두 보낸다. `accept`를 생략하면 보관된 후보 전체가 선택되므로 확인한 인덱스 배열을 명시한다. 박스가 수백 개면 확인 가능한 묶음으로 나누고, 각 묶음을 다음 미리보기 전에 적용한다. 이미지나 대상 라벨 상태가 바뀌었거나 결과 ID가 만료됐으면 다시 미리본다.

## 기존 마스크 검수와 수정

1. `analyze_masks`에서 요청과 관련된 누락·잡티·구멍·합침·경계 후보만 확인한다. 검수 요청이면 후보 수와 근거를 보고한다.
2. **누락**은 해당 영역만 `segment_ai`로 미리보기하고 `backgroundOnly:true`로 기존 픽셀을 보호한다. **개별 영역의 삭제·클래스 수정**은 `get_regions`에서 현재 `seed`를 읽고 `edit_regions`를 사용한다. 마스크가 바뀌면 `seed`를 다시 읽는다.
3. **여러 영역에 같은 정리 규칙**이 필요하면 `clean_masks`에 그 옵션만 넣고 `apply:false`로 미리보기한다. 실제 작은 물체나 보존할 구멍을 제거하는지 확인하고, 적용 요청이 있으면 같은 옵션으로 실행한다. 폴더 정리는 [폴더 일괄 작업](FOLDER.md)을 따른다.

## 결과 확인과 저장

- 적용 건수와 결과 마스크의 영역 수를 따로 기록한다. `get_regions {"limit":0}`으로 클래스별 픽셀·영역 수를 확인하고 `analyze_masks`로 누락·합침 후보의 변화를 확인한다. 정답이 있으면 `compare_masks`로 IoU·경계 F1·누락·과잉·클래스 오류를 함께 본다. 의도 밖의 합침이나 소실이 확인되면 저장 전에 해당 변경을 되돌린다. [SEM 표본](../BENCHMARK.md#segmentation-표본과-자동화)에서는 정리 후 IoU가 올랐지만 누락은 31개에서 80개로 늘었다.
- 저장 요청이면 [공통 저장 절차](../MCP_PLAYBOOK.md#저장-경로와-결과-확인)로 실제 경로, 클래스별 픽셀 수와 연결 영역 수를 대조한다. 확인한 후보·적용 수·저장 여부·남은 검수를 보고하고 종료한다.

모델이나 클라이언트를 비교할 때는 같은 이미지와 정답 마스크를 담은 복사본에서 빈 마스크 생성과 기존 마스크 보완을 각각 실행한다. 저장 후 품질과 요청부터 최종 보고까지의 시간, MCP 호출·캡처 수, 미확정 후보 수를 함께 기록한다.
